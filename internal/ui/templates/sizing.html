Sizing — nodes

The fleet-sizing pipeline: NS8 cluster leaders post one report per complete UTC day, one entry per node, carrying utilization percentiles, stress durations and each module family's workload counts. A system_id is a cluster, so one report normally carries several nodes. Pressure is a 0–100 number computed on the server — 0 means no pressure, 100 means severe — and n/a means it was deliberately not computed: a node that was switched off for eighteen hours is not a low-pressure node. Utilization percentiles are shown next to it because pressure answers “is this undersized” and the percentiles answer “how much headroom is left”, which are different questions.

Latest day per node

Verdict is a multi-day answer, not this day's: k-of-n over a trailing window with hysteresis, because undersizing is recurrence and a single bad day is not a verdict. Top axis is mixed when no single axis dominated the bad days — seven bad days from seven unrelated causes is not one verdict, and recommending RAM on that evidence would be wrong. Placement is the question only a cluster can be asked: with two or more nodes and a wide spread of memory utilization the answer is “rebalance”, not “buy hardware”.

Module inventory and workload

What is installed on each node, on that node's most recent day. facts_ok is load-bearing: get-facts fails per instance, and a zero mailbox count from a failed call is indistinguishable from a genuinely empty mail server — so a family whose facts call failed is treated as unknown rather than as idle. Every workload value is a number, and that is the whole privacy control: an FQDN, an IP address, a hostname or a DMI serial cannot be encoded in a float.

Score thresholds

Every knee and ceiling the pressure score depends on, labelled with how it was arrived at. Most of them are guesses, to be calibrated once about thirty days of fleet data exist — set each noisy knee at the fleet p90 and each ceiling at the fleet p99, leave the physical knees fixed, bump the formula version and recompute. Storing every input as its own column is what makes that a one-pass operation needing no fleet cooperation. They are labelled here rather than presented as advice.

Ingest accounting

What each cluster contributed and what was dropped before storage, per day. The measurement rows recompute — a day is an absolute fact, so the second and third of a reporter's three daily sends are byte-identical restatements — while these counters accumulate. So three sends of one day show three reports and exactly one set of measurements, which is how “this cluster posts and stores nothing, and here is the rule dropping it” stays answerable.
