Sizing — cohorts

What the fleet's own hardware says a given deployment needs. Every number here is observed peak demand in absolute bytes and cores, not utilization: utilization is a property of hardware someone happened to buy, and the deliverable is advice on what to buy. The recommendation is the p90 column.

No per-module cost is measured here, and none is available from this stack. Nothing in NS8 exports per-container memory or CPU — there is no cAdvisor and no cgroup exporter — so a module's cost can only ever be inferred from variation across nodes. These are measured percentiles of whole nodes grouped by what they run, which is a different and more honest claim.

Workload buckets

Deterministic t-shirt sizes, split at the p33 and p66 of each metric across nodes. Quantile bucketing rather than clustering, because it gives the same sizes and is stable run to run — a number published to customers must not change unless the data changed. An empty to means no upper bound: a finite ceiling on the top bucket would silently drop the largest deployment.

What “censored” means, and why it is published

An undersized node's memory demand is capped by the memory it has: a node needing 12 GiB but holding 8 reports about 7.6 GiB. Feeding that into an estimator of “how much RAM does a mail node need” makes the answer come out too small, which then declares more nodes adequately sized — the exact inverse of what this feature is for. That is systematic bias, not noise: no volume of data and no choice of model removes it. So a node whose memory utilization reached {{fmtFracVal .CensorRAMUtil}}, or that swapped in, or that suffered an OOM kill, is excluded from the percentiles — its true demand is unobservable — and counted in the censored column instead. A cohort that is 40 % censored means the fleet's own hardware for that profile is systematically too small, which is the most valuable finding this pass can produce.

Note what is deliberately not excluded. Disk-bound nodes stay in: they are precisely the nodes whose existence is the answer, and iowait is not a covariate of a memory baseline anyway. Nodes are not excluded for being “unhealthy” in general either — “what a healthy node uses”, derived by deleting the unhealthy ones, is survivorship bias with extra steps. Censoring is the only health-shaped exclusion here and it is justified by measurability, not by health. And an idle instance is bucketed rather than dropped: a mail server with zero mailboxes gives the floor cost of running the module, which people want — it just is not a “mail node”.
