Gate

Analyses grouped by their exact set of gate reasons, fleet-wide — the answer to "why are we paying". A reason set is not a description of a window, it is the trigger: the gate calls the AI if and only if at least one reason fired, so every row below with reasons went to the AI, and the (none) row is the windows that were gated out for free. A window can have several reasons at once (e.g. a new template and a deviating module); this groups on the whole combination, so the same reason mixed with different others counts as separate rows. The number to watch is the gated out share above: that is the gate doing its job.

Scope matters here. Gate reasons are stored spelled exactly as the formula that produced them spelled them, so all time mixes eras — rows written before the security condition became novelty-scoped say security_category and carry embedded counts and ratios (new_templates=5, deviation:/3=3.03), which group separately and describe a gate that no longer exists.
